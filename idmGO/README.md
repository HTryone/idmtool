# IDMFrost — IDM 试用守护

一键冻结 IDM 试用期，并自动维持。**两个 exe：界面/激活一个，守护一个。**

> 仅供学习研究 Windows 注册表 ACL 与 IDM 行为，请支持正版。

## 使用

```
把 idmfrost.exe、idmguard.exe 放同一目录
双击 idmfrost.exe  →  UAC 点「是」  →  点「一键完成」
```

完事。激活完成时后台守护会被立即拉起，同时写入开机自启；之后 IDM 一直可用，开机自动守护，无需再打开本工具。

## 界面

| 按钮 | 作用 |
|---|---|
| **一键完成** | 重置试用计数 → 启动 IDM 重建试用键 → 锁死 → 写配置 + 装开机自启 + 拉起守护 |
| **回滚** | 停守护 → 禁用自启 → 删自启 → 解锁删键 → 清注册信息 → 恢复原状 |
| **退出** | 随时可关；执行中也能立即退出（关掉界面不影响后台守护） |

## 两个程序（进程程序与激活程序分离）

| 文件 | 职责 | 生命周期 |
|---|---|---|
| `idmfrost.exe` | 界面 + 激活，操作注册表 | 只在用户双击期间 |
| `idmguard.exe` | 纯守护，无窗口、单实例 | 常驻后台 |

**激活是一次性的，守护是长期的**——所以拆成两个进程：

- 点「一键完成」时，`idmfrost.exe` 会立即 `exec` 一个 `idmguard.exe`（脱离父进程），
  然后把守护写进开机启动文件夹。界面随后可直接关掉，守护照跑。
- `idmguard.exe` 用 `Global\` 命名互斥保证**单实例**：重复启动会立即退出，不会出现两个守护打架。
- 开机自启的快捷方式直接指向 `idmguard.exe`，参数 `--quiet`。

守护循环：

```
每 6 小时检查一次（刚补过锁则加密到 5 分钟）
├── 读 config.json：enabled=false 或文件缺失 → 静默待着，不碰任何东西
├── 试用键都锁着 → 无需动作
├── 有未锁的键（IDM 更新重写了）→ 立即补锁
└── 键被删了 → 启动 IDM 重建 → 锁死
```

**顺序护栏**：守护的前提是「配置文件 enabled=true」（=用户点过一键完成）。条件不成立就完全静默——不碰注册表、不启 IDM、不报错。

## 数据目录（exe 同级 data\）

```
dist\
├── idmfrost.exe            界面 + 激活
├── idmguard.exe            后台守护
└── data\
    ├── config.json          配置（enabled / installed_at / last_seen / exe_path）
    └── log\
        ├── 2026-11-25.log   当天的守护日志
        ├── 2026-11-24.log
        └── ...              仅保留最近 5 天，第 6 天自动删除
```

- 日志**按天一个文件**（`YYYY-MM-DD.log`），写入时自动清理超过 5 天的旧文件
- 单日文件超 4MB 停止写入（防爆盘，不截断历史）
- 程序**每次启动都写配置**（刷新 `last_seen`），文件永远存在，不会因缺失误判
- 回滚把 `enabled` 置 false → 守护下次 tick 自己静默退出

## 原理（实测结论）

IDM 6.43 判断试用是否过期，看的是：

```
HKCU\Software\Classes\WOW6432Node\CLSID\{07999AC3-058B-40BF-984F-69EB1E554CA7}
    Model = 328    ← 到期信息在这里
```

用 Deny ACL 锁死该键，IDM 读不到 → 永远按「未过期」处理。

| 实测 | 结果 |
|---|---|
| 用用户权限**写**锁死的键 | `错误码 5` 拒绝 |
| 用用户权限**删**锁死的键 | 拒绝，`TakeOwnership` 都打不开 |
| 连启 IDM 8 次 | 锁始终有效，无过期弹窗 |
| `radxcnt` 改 999/9999 | 依然正常 → **radxcnt 不是判定依据** |
| 清键后仅启动 IDM（不下载） | 键自动重建 → **不需要触发下载** |


## 守护的触发条件与资源控制

### 什么时候才动

| 情况 | 行为 |
|---|---|
| 键已锁死（正常态） | **什么都不做**，连 IDM 都不碰 |
| 有未锁的键（IDM 更新重写了） | 只做注册表补锁，**不启动、不杀 IDM** |
| 键丢失 + IDM **未运行** | 临时启动 IDM 重建键，用完**只关自己拉起的那个进程** |
| 键丢失 + IDM **正在运行** | 完全不动它，等 IDM 自己写键（最多等 8 秒） |

### 用户无感保证

- 守护**从不** `taskkill /im idman.exe`，只 `cmd.Process.Kill()` 自己 `exec.Command` 起来的那个进程
- IDM 正在下载时，守护绝不重启它；正在下的文件不受任何影响
- 只有用户**主动点**「一键完成 / 回滚」时才会关 IDM（界面上会明说）

### 失败不反复（熔断）

- 连续失败 **3 次** → 进入 **6 小时冷却**，期间不再启动 IDM、不再锁键、不写重复日志
- 冷却期结束才允许再试；一旦成功立即清零
- 状态页会显示：`熔断中：连续失败，X 后再试`

这样最坏情况只是"每 6 小时试一次、连试 3 次后歇 6 小时"，绝不会 5 分钟一次疯狂重试把资源打满。

### 关于"还剩几天到期"

IDM 把到期信息编码在锁死的 `Model` 值里，**锁上之后自己也读不到**，所以守护无法精确报"还剩 N 天"。它采用的策略是状态驱动：
- 键好着 → 不管
- 键没了/被解锁 → 立即重建并锁死

这比猜天数更可靠 —— 无论到期日怎么算，只要锁失效就补。
## 为什么是「冻结」而不是「激活」

激活要写随机序列号，IDM 6.42+ 联网校验后判为**假冒序列号**，弹窗甚至让 IDM 自动退出。冻结不写序列号、不触发校验。

## 命令行

```
idmfrost.exe --oneclick        一键完成（冻结 + 拉起守护 + 装开机自启）
idmfrost.exe --rollback        回滚（停守护 + 删自启 + 解锁删键）
idmfrost.exe --autofix         单次补锁（诊断/手动，不常驻）
idmfrost.exe --status          查看状态
IDMTOOL_TEST=1                 自测模式（不写注册表/不锁键）

idmguard.exe                   常驻守护（无窗口、单实例；开机自启调用）
idmguard.exe --quiet           同默认（兼容保留）
```

## 构建

```
双击 idmGO\build.bat    →  产物：dist\idmfrost.exe + dist\idmguard.exe
```

两个 exe 共用同一份 `assets\idmfrost.ico`，图标完全一致。

## 关键实现坑

1. `RegSetKeySecurity` 的 ACE 必须用 **SID**（`S-1-1-0`），用名字 `"Everyone"` 在中文系统会静默生成空 ACL。
2. `ACCESS_MODE`：`GRANT=1 SET=2 DENY=3`。**deny 写成 1 会变成 Everyone 完全控制**。
3. Deny ACE 必须基于**现有 DACL** 追加，才排最前生效。
4. HKCU 键**无需管理员**（当前用户有 WRITE_DAC）；只有 HKLM 才要提权。
5. Go 写 Win32 GUI 必须 `runtime.LockOSThread()`，否则消息循环跑错线程 → 窗口"未响应"。
6. 外部进程 `Kill()` 后必须 `Wait()`，否则僵尸进程导致界面卡死。
7. 锁键验证不能用提权进程自己试（管理员 token 有特权可绕过）。
8. **守护拆分**：`idmguard.exe` 是独立过程，`idmfrost.exe` 用 `cmd.Process.Release()` 拉起后不 Wait，
   保证界面关掉后守护仍独立存活；守护自身用 `Global\` 命名 Mutex 做单实例。
